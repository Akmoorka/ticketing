# ADR-0003: секреты только из окружения

Статус: принято. Дата: 2026-11-05.

## Контекст
Порог входа для проверяющего: `git clone` → `cp .env.example .env` → `docker compose up -d`. При этом в репозитории не должно быть секретов (P-11).

## Варианты
- A. В `.env.example` лежат рабочие dev-значения.
- B. В `.env.example` секреты пустые; у dev есть значения по умолчанию, у prod их нет.

## Решение
B. `SECRET_KEY` и `DB_PASSWORD` пустые в `.env.example`. В `config/settings/dev.py` и в `docker-compose.yml` для них есть явно помеченные dev-значения. В `config/settings/prod.py` пустой `SECRET_KEY` вызывает `ImproperlyConfigured`.

## Почему
Система поднимается на чистой машине без ручных шагов, а забытый секрет на стенде приводит к громкой ошибке, а не к тихому запуску с известным ключом.

## Цена
Пароль dev-базы известен из `docker-compose.yml`. Это допустимо, потому что порт БД наружу не публикуется. Для prod `docker-compose.prod.yml` обязан требовать значения (`${VAR:?}`).
